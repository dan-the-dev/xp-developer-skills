# Principles

AMPD is strongly inspired by Extreme Programming, Lean Software Development, Agile Product Development and Continuous Delivery.

The framework does not try to replace these disciplines.

It tries to amplify them through AI.

This document defines the foundational principles guiding:

* the framework
* the repository structure
* the skills
* the workflows
* the expected behavior of AI agents operating inside the system

⸻

## Core Philosophy

AI should amplify engineering discipline, not bypass it.

The faster AI becomes, the more important:

* feedback loops
* testing
* architecture
* observability
* simplicity
* product validation
* iterative delivery

become.

AMPD assumes that removing engineering discipline from AI-assisted development creates:

* fragile systems
* context decay
* architectural entropy
* unsafe delivery
* unmaintainable software

The framework therefore focuses on:

* structured workflows
* explicit feedback loops
* repository-native context
* executable engineering practices
* continuous validation

⸻

## XP Values Amplified By AI

AMPD is deeply inspired by the five core values of Extreme Programming.

⸻

### Communication

Shared understanding is one of the main bottlenecks in software development.

AI can amplify communication through:

* repository-native context
* continuously updated documentation
* structured architectural knowledge
* executable workflows
* operational memory systems

The goal is not more documentation.

The goal is:
high-signal shared context.

⸻

### Simplicity

Complexity compounds over time.

AI should amplify simplicity by:

* suggesting minimal solutions
* reducing accidental complexity
* encouraging small increments
* helping enforce architectural boundaries
* automating repetitive work

AMPD strongly favors:
the simplest solution that works today.

⸻

### Feedback

Fast feedback is the core accelerator of software development.

AI dramatically increases the speed of:

* test execution
* validation
* experimentation
* refactoring
* observability
* product learning

AMPD treats feedback loops as the central design principle of the framework.

⸻

### Courage

AI lowers the operational cost of change.

This should increase the team’s ability to:

* refactor aggressively
* experiment safely
* challenge assumptions
* remove bad solutions
* iterate continuously

But courage without discipline creates chaos.

AMPD balances courage with:

* testing
* validation
* observability
* incremental delivery

⸻

### Respect

Software is built by humans.

AI systems should support:

* collaboration
* clarity
* sustainability
* learning
* healthy engineering practices

The framework rejects:

* AI-generated chaos
* opaque automation
* unsafe acceleration
* disposable engineering

AMPD is human-centered engineering.

⸻

## Engineering Principles

⸻

### Repository As Operational Context

The repository is not only source code.

It is:

* architectural memory
* operational knowledge
* workflow definition
* engineering context
* product understanding

AI systems should operate primarily from repository-native knowledge.

⸻

### Documentation Must Stay Lightweight

Documentation should:

* explain decisions
* explain workflows
* explain architecture
* explain intent

Documentation should NOT:

* duplicate code
* describe obvious implementation details
* become stale process overhead

The framework strongly prefers:
small focused documents over massive centralized documentation.

⸻

### Tests Are The Main Validation System

AMPD treats tests as:
the primary executable specification of the system.

This includes:

* unit tests
* integration tests
* acceptance tests
* characterization tests
* architectural fitness tests
* observability validation

AI agents should trust tests more than assumptions.

⸻

### Feedback Loops Over Big Design

AMPD strongly favors:

* incremental delivery
* iterative validation
* small changes
* short loops
* progressive refinement

The framework rejects:
large speculative design phases disconnected from implementation feedback.

⸻

### Safe Autonomy

AI agents should operate autonomously only inside constrained systems.

Autonomy requires:

* clear boundaries
* explicit workflows
* strong validation
* testing
* observability
* rollback capability

The goal is not unrestricted automation.

The goal is:
safe accelerated delivery.

⸻

### Context Quality Over Context Quantity

Large context is not necessarily good context.

AMPD favors:

* layered context
* scoped documentation
* contextual loading
* signal over noise
* operational clarity

Poor context creates poor AI behavior.

⸻

### Continuous Refactoring

Software quality decays continuously.

AI should amplify:

* safe refactoring
* architectural consistency
* simplification
* removal of accidental complexity

Refactoring is not optional maintenance.

It is continuous system preservation.

⸻

### Observability As Product Feedback

Observability is not only technical monitoring.

AMPD treats observability as:

* operational feedback
* product validation
* behavioral learning
* experimentation support

Both technical and product metrics matter.

⸻

## AI Operational Principles

⸻

### AI Should Follow Workflows

AI systems should not improvise core engineering workflows.

Skills exist to:

* encode discipline
* standardize execution
* reduce unsafe behavior
* improve repeatability

The framework favors:
structured operational behavior over freeform prompting.

⸻

### Small Changes Over Large Generations

Large uncontrolled code generation increases risk.

AMPD strongly favors:

* micro-iterations
* small commits
* continuous verification
* progressive integration

AI should optimize for:
reviewability and safety.

⸻

### Explicit Validation Over Assumption

AI agents should:

* verify behavior
* run tests
* validate assumptions
* confirm outcomes

instead of assuming correctness.

⸻

### Human Oversight Remains Essential

AMPD does not assume fully autonomous engineering.

Humans remain responsible for:

* strategy
* architecture
* prioritization
* product direction
* final validation
* ethical decisions

AI amplifies engineering systems.

Humans remain accountable for them.

⸻

## Long-Term Principle

The framework itself should continuously evolve.

No principle should become dogma.

AMPD promotes:

* experimentation
* reflection
* iterative learning
* continuous improvement

The framework should evolve exactly like the systems it promotes:
through feedback, learning and adaptation.
